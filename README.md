## CRUD API

This is the implementation of simple CRUD API using in-memory DB.

### Getting Started

#### Please clone the repisitory to your pc:

```bash
 git clone https://github.com/antonina220590/node-nodejs-crudapi.git
```

#### Install dependencies:

```bash
npm install
```

#### Configuration

Before running the application, you might need to configure the port it runs on. This is done via a .env file in the root of the project.

Create a file named .env in the root directory of the project.

Add the following content to it, adjusting the port number if needed:

```bash
PORT=4000
```

#### Running the Application

Development Mode:

```bash
npm run start:dev
```

Production Mode (Single Node):

```bash
npm run start:prod
```

Multi-node Mode (Cluster with Load Balancer):

```bash
npm run start:multi
```

#### Build

```bash
npm run build
```

#### Lint

```bash
npm run lint
```

#### Lint Fix

```bash
npm run lint:fix
```

#### Test

For the API tests to run correctly, the server should be running in a separate terminal, preferably in multi-node mode to test the full functionality including IPC and load balancing.

Start the server:

```bash
npm run start:multi
```

In a new terminal, run tests:

```bash
npm run test
```

### API Endpoints / Usage

The API provides endpoints to manage user records. All user data is stored in-memory.

Base URL: http://localhost:{PORT} (e.g., http://localhost:4000 when running npm run start:multi or as configured in your .env file)

1. Get All Users

- Endpoint: GET /api/users
- Description: Retrieves a list of all user records.
- Request Body: None.
- Successful Response (200 OK): An array of user objects.

```
[
  {
    "id": "a1b2c3d4-e5f6-7890-1234-567890abcdef",
    "username": "John Doe",
    "age": 30,
    "hobbies": ["reading", "hiking"]
  },
  {
    "id": "b2c3d4e5-f6a7-8901-2345-678901bcdef0",
    "username": "Jane Smith",
    "age": 25,
    "hobbies": ["coding", "music"]
  }
]
```

2. Get User by ID

- Endpoint: GET /api/users/{userId}
- Description: Retrieves a specific user by their unique ID.
- Path Parameters:

  userId (string, UUID format): The ID of the user to retrieve.

- Request Body: None.
- Successful Response (200 OK): The user object if found.

```
{
  "id": "a1b2c3d4-e5f6-7890-1234-567890abcdef",
  "username": "John Doe",
  "age": 30,
  "hobbies": ["reading", "hiking"]
}
```

Error Responses:

400 Bad Request: If the userId is not a valid UUID.

```
{
  "message": "Error 400: userId 'invalid-uuid' is not a valid UUID"
}
```

404 Not Found: If a user with the specified userId does not exist.

```
{
  "message": "Error 404: User with ID 'non-existent-uuid' is not found"
}
```

500 Internal Server Error: If a server-side error occurs.

3. Create New User

- Endpoint: POST /api/users
- Description: Creates a new user record. The id for the new user will be generated by the server.
- Request Body: A JSON object with the following properties:
  - username (string, required)
  - age (number, required)
  - hobbies (array of strings, required, can be an empty array [])

```
{
  "username": "Alice Wonderland",
  "age": 28,
  "hobbies": ["exploring", "tea parties"]
}
```

Successful Response (201 Created):

```
{
  "id": "c3d4e5f6-a7b8-9012-3456-789012cdef01",
  "username": "Alice Wonderland",
  "age": 28,
  "hobbies": ["exploring", "tea parties"]
}
```

Error Responses:

400 Bad Request: If the request body is missing required fields, or if fields have incorrect data types.

```
{
  "message": "Error 400: Request body does not contain required fields (username, age, hobbies)"
}

{
  "message": "Error 400: Request body does not contain required fields (username, age, hobbies)"
}
```

500 Internal Server Error: If a server-side error occurs.

4. Update User

- Endpoint: PUT /api/users/{userId}
- Description: Updates an existing user record identified by userId.
- Path Parameters:

  - userId (string, UUID format): The ID of the user to update.

- Request Body: A JSON object with the fields to update. All fields (username, age, hobbies) are required, similar to the POST request.

```
{
  "username": "Alice Kingsleigh",
  "age": 29,
  "hobbies": ["exploring", "chess"]
}
```

Successful Response (200 OK): The updated user object.

```
{
  "id": "c3d4e5f6-a7b8-9012-3456-789012cdef01", // ID remains the same
  "username": "Alice Kingsleigh",
  "age": 29,
  "hobbies": ["exploring", "chess"]
}
```

Error Responses:

```
{
  "message": "Error 400: userId 'invalid-uuid' is not a valid UUID"
}

{
  "message": "Error 400: userId 'invalid-uuid' is not a valid UUID"
}

{
  "message": "Error 404: User with ID 'non-existent-uuid' not found"
}

```

5. Delete User

- Endpoint: DELETE /api/users/{userId}
- Description: Deletes an existing user record identified by userId.
- Path Parameters:

  - userId (string, UUID format): The ID of the user to delete.

- Request Body: None.
- Successful Response (204 No Content): An empty response body indicating successful deletion.

Error Responses:

```
{
  "message": "Error 400: User ID 'invalid-uuid' is not a valid UUID"
}

{
  "message": "Error 404: User with ID 'non-existent-uuid' not found"
}

```
